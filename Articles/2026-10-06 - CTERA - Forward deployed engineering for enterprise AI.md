# Forward deployed engineering for enterprise AI

[Read the press release](https://www.ctera.com/news/ctera-introduces-forward-deployed-engineering-to-close-the-ai-skills-gap-and-accelerate-enterprise-deployments/).

## Summary

CTERA announces small teams pairing a Forward Deployed Engineer with a Deployment Strategist inside a customer's project team. The stated engagement sequence is discovery and data grounding, a first production use case, expansion to additional workflows, and handover for independent operation.

Its implementation principles are to inspect the actual data environment, prepare and govern the needed data, integrate with existing workflows, validate against real data before launch, and have customer engineers co-build and document from the first phase. CTERA defines completion as the customer being able to add the next use case without CTERA.

## Extracted model

[Ground-prove-expand-transfer delivery](../Operating%20models/Ground-prove-expand-transfer%20delivery.md) generalises the sequence as ground, prove, expand, and transfer. This is vault shorthand, not terminology used by CTERA. The most reusable feature is the transition from a first production use case to an independently repeatable next use case; it connects delivery, reuse, and handover without assuming that the first implementation is automatically scalable.

## Perspective and limits

This is a service-launch press release describing intended practice, not observed engagement results. The page provides no duration, outcome measurements, acceptance evidence, maintenance terms, or examples of a customer independently adding another use case. Its skills-gap and architectural-bottleneck statistics are attributed to Futurum but were not verified against the underlying survey.

"Start from the data" reflects CTERA's unstructured-data product context. A broader transfer should start from direct evidence in the operating environment—data, workflows, permissions, systems, and user knowledge—rather than make data the universal first object of every engagement.

## Connections

The model strengthens the transition test in [Customer-owned delivery](../Operating%20models/Customer-owned%20delivery.md) and gives [FDE](../FDE.md#executing-more-effectively) a phased candidate for comparison with [Atlassian co-engineering](../Operating%20models/Atlassian%20co-engineering.md). It does not describe a field-to-product feedback loop, so it should not be used as evidence for [Product-oriented FDE](../Operating%20models/Product-oriented%20FDE.md).
